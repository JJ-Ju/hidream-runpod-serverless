# Client API Guide

This guide is for GUI, backend, and pipeline clients that call the HiDream O1
RunPod Serverless endpoint.

The worker is a RunPod queue worker, not a direct HTTP server. A client calls the
RunPod endpoint API, and RunPod delivers `body.input` to the worker handler.
Use RunPod's `/runsync` operation for simple blocking requests, or `/run` plus
`/status/{job_id}` for long-running UI jobs. See RunPod's endpoint request docs:
<https://docs.runpod.io/serverless/endpoints/send-requests>.

Do not put a RunPod API key in a public browser app. For public GUIs, create a
small backend route that accepts the user's form/image data, adds the RunPod API
key server-side, calls RunPod, and returns only the worker result to the browser.

## Endpoints

Replace `<ENDPOINT_ID>` and `<RUNPOD_API_KEY>` with your RunPod values.

Synchronous request:

```http
POST https://api.runpod.ai/v2/<ENDPOINT_ID>/runsync
Authorization: Bearer <RUNPOD_API_KEY>
Content-Type: application/json
```

Asynchronous request:

```http
POST https://api.runpod.ai/v2/<ENDPOINT_ID>/run
Authorization: Bearer <RUNPOD_API_KEY>
Content-Type: application/json
```

Poll an async job:

```http
GET https://api.runpod.ai/v2/<ENDPOINT_ID>/status/<JOB_ID>
Authorization: Bearer <RUNPOD_API_KEY>
```

Cancel an async job:

```http
POST https://api.runpod.ai/v2/<ENDPOINT_ID>/cancel/<JOB_ID>
Authorization: Bearer <RUNPOD_API_KEY>
```

## Request Envelope

RunPod requests wrap worker fields inside `input`:

```json
{
  "input": {
    "prompt": "Clean this render for a downstream 3D model generation stage.",
    "input_image": {
      "base64": "<base64-encoded-source-image>",
      "mime_type": "image/png"
    },
    "output_delivery": "base64"
  }
}
```

## Input Fields

Required:

- `prompt`: non-empty string.

Optional:

- `input_image`: direct single-image payload object for edit/image-to-image
  jobs.
- `input_images`: direct multi-image payload objects for reference or layout
  jobs.
- `ref_image`, `init_image`, `image`: single-image aliases for `input_image`.
- `ref_images`: canonical upstream-style alias for `input_images`.
- `width`, `height`: integers up to `2048`, default `2048`.
- `seed`: integer, default `32`.
- `model_type`: `full` or `dev`, default `full`.
- `layout_bboxes`: one normalized `[x1, x2, y1, y2]` box per input image.
- `keep_original_aspect`: boolean, default `false`.
- `editing_scheduler`: `flow_match` or `flash`, default `flow_match`.
- `guidance_scale`, `shift`, `noise_scale_start`, `noise_scale_end`,
  `noise_clip_std`: advanced scheduler knobs.
- `output_format`: `png`, `webp`, or `jpeg`, default `png`.
- `output_delivery`: `base64`, `url`, or `both`. Endpoint default comes from
  `DEFAULT_OUTPUT_DELIVERY`.

## Direct Image Payloads

Preferred direct form:

```json
{
  "base64": "<base64-encoded-image-without-data-uri-prefix>",
  "mime_type": "image/png"
}
```

Also accepted:

```json
{
  "data_uri": "data:image/png;base64,<base64-encoded-image>"
}
```

Compatibility forms are accepted too: plain base64 strings, public image URLs,
and presigned image URLs. For GUI and 3D pipeline flows, direct payload objects
are the recommended shape because they avoid temporary input buckets.

Limits:

- Up to 10 input images.
- Each direct or downloaded input image payload must be 20 MB or smaller.
- Local file paths and private-network URLs are rejected by the worker.

## Modes

The worker infers mode from the image fields:

- `text_to_image`: no `input_image` or `input_images`.
- `edit`: exactly one input image.
- `reference`: two or more input images.
- `layout_reference`: input images plus `layout_bboxes`.

The inferred mode is returned as `output.mode`.

## Direct Input, Direct Output

Use this for a GUI or pipeline that sends source image bytes directly and wants
generated bytes directly back.

```json
{
  "input": {
    "prompt": "Convert this source render into a clean orthographic asset image.",
    "input_image": {
      "base64": "<base64-encoded-source-image>",
      "mime_type": "image/png"
    },
    "keep_original_aspect": true,
    "output_format": "png",
    "output_delivery": "base64"
  }
}
```

The worker output includes:

```json
{
  "image_base64": "<base64-encoded-generated-image>",
  "content_type": "image/png",
  "image_size_bytes": 123456,
  "seed": 32,
  "width": 2048,
  "height": 2048,
  "mode": "edit",
  "model_id": "HiDream-ai/HiDream-O1-Image",
  "attention_backend": "sdpa"
}
```

## TypeScript Types

```ts
type ImagePayload =
  | { base64: string; mime_type?: string; content_type?: string }
  | { data_uri: string }
  | { url: string }
  | { image_url: string }
  | string;

type OutputFormat = "png" | "webp" | "jpeg";
type OutputDelivery = "base64" | "url" | "both";
type ModelType = "full" | "dev";
type EditingScheduler = "flow_match" | "flash";

interface HiDreamInput {
  prompt: string;
  input_image?: ImagePayload;
  input_images?: ImagePayload[];
  ref_image?: ImagePayload;
  init_image?: ImagePayload;
  image?: ImagePayload;
  ref_images?: ImagePayload[];
  width?: number;
  height?: number;
  seed?: number;
  model_type?: ModelType;
  layout_bboxes?: [number, number, number, number][];
  keep_original_aspect?: boolean;
  editing_scheduler?: EditingScheduler;
  guidance_scale?: number;
  shift?: number;
  noise_scale_start?: number;
  noise_scale_end?: number;
  noise_clip_std?: number;
  output_format?: OutputFormat;
  output_delivery?: OutputDelivery;
}

interface HiDreamOutputBase {
  seed: number;
  width: number;
  height: number;
  mode: "text_to_image" | "edit" | "reference" | "layout_reference";
  model_id: string;
  attention_backend: "sdpa" | "flash" | "auto" | string;
  output_delivery: OutputDelivery;
  content_type: string;
  image_size_bytes: number;
}

type HiDreamOutput = HiDreamOutputBase & {
  image_base64?: string;
  image_url?: string;
  bucket?: string;
  key?: string;
  error?: string;
};

interface RunPodResponse<T> {
  id: string;
  status: "IN_QUEUE" | "IN_PROGRESS" | "COMPLETED" | "FAILED" | "CANCELLED" | string;
  output?: T;
  error?: string;
  delayTime?: number;
  executionTime?: number;
  workerId?: string;
}
```

## JavaScript Client Example

Use this in a trusted backend route, not in a public browser bundle.

```ts
async function runHiDreamSync(input: HiDreamInput): Promise<HiDreamOutput> {
  const endpointId = process.env.RUNPOD_ENDPOINT_ID;
  const apiKey = process.env.RUNPOD_API_KEY;
  if (!endpointId || !apiKey) {
    throw new Error("RUNPOD_ENDPOINT_ID and RUNPOD_API_KEY are required");
  }

  const response = await fetch(`https://api.runpod.ai/v2/${endpointId}/runsync`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${apiKey}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ input }),
  });

  if (!response.ok) {
    throw new Error(`RunPod HTTP ${response.status}: ${await response.text()}`);
  }

  const result = (await response.json()) as RunPodResponse<HiDreamOutput>;
  if (result.error) {
    throw new Error(result.error);
  }
  if (result.output?.error) {
    throw new Error(result.output.error);
  }
  if (result.status !== "COMPLETED") {
    throw new Error(`RunPod job ended with status ${result.status}`);
  }
  if (!result.output) {
    throw new Error("RunPod response did not include output");
  }
  return result.output;
}
```

## Browser File To Payload

This helper can run in the browser before sending data to your own backend
route. It strips the data URI prefix because the preferred worker shape keeps
MIME type separate.

```ts
async function fileToImagePayload(file: File): Promise<{ base64: string; mime_type: string }> {
  const dataUrl = await new Promise<string>((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = () => resolve(String(reader.result));
    reader.onerror = () => reject(reader.error);
    reader.readAsDataURL(file);
  });

  const [, base64 = ""] = dataUrl.split(",", 2);
  return {
    base64,
    mime_type: file.type || "image/png",
  };
}
```

## Rendering Direct Output In A GUI

For `output_delivery=base64`, render the generated image with a data URL:

```ts
function imageSrcFromOutput(output: HiDreamOutput): string {
  if (output.image_url) {
    return output.image_url;
  }
  if (output.image_base64) {
    return `data:${output.content_type};base64,${output.image_base64}`;
  }
  throw new Error("Output did not include image_url or image_base64");
}
```

## Async UI Pattern

Use `/run` when generation may take longer than your frontend timeout. The
initial response returns a job ID. Store that ID in UI state, poll `/status`, and
show progress states based on `status`.

Recommended GUI states:

- `idle`: no request in flight.
- `uploading`: browser is reading/encoding input images.
- `queued`: `/run` returned an ID and status is `IN_QUEUE`.
- `generating`: status is `IN_PROGRESS`.
- `complete`: status is `COMPLETED` and `output` contains image data or URL.
- `failed`: HTTP error, RunPod `error`, or worker `output.error`.
- `cancelled`: user cancelled the job or RunPod returned `CANCELLED`.

## Common Errors

- `S3 output storage is not configured`: request used `output_delivery=url` or
  `both`, but the endpoint does not have the required `S3_*` environment
  variables. Use `output_delivery=base64` or configure S3.
- `Cached model not found`: the RunPod endpoint Model field has not prepared
  `HiDream-ai/HiDream-O1-Image` at
  `/runpod-volume/huggingface-cache/hub`, or `HIDREAM_MODEL_PATH` points to the
  wrong local directory.
- `prompt must be a non-empty string`: GUI submitted an empty prompt.
- `width must be no greater than 2048` or `height must be no greater than
  2048`: clamp GUI controls to 2048.
- `ref_images cannot contain more than 10 entries`: limit multi-image upload UI
  to 10 images.
- `base64 payloads are too large`: compress or resize the input image before
  sending it.
- `private or local network`: URLs must be public or presigned; direct base64
  payloads avoid this path.
